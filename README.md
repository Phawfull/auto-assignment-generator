# Tutorial to Word

Double-click **Start Tutorial Maker.bat**. Choose a Word `.docx` tutorial, enter your full name and registration number, open **AI and MySQL settings**, and enter your OpenAI API key and MySQL login. Click **Generate Word document**.

The main Python file is `tutorial_maker.py`. The subject defaults to APP — Advanced Programming Practice. No IntelliJ setup is needed: the app uses the installed Java compiler directly.

## Reading the code

Start with `workflow.py` to follow a complete run. Each file has one main job:

- `tutorial_maker.py` contains the small desktop form.
- `workflow.py` handles questions, retries and progress.
- `ai_answers.py` requests and checks Java answers.
- `java_programs.py` compiles programs and collects screenshots.
- `word_document.py` reads tutorials and writes the final document.
- `settings.py` holds shared defaults and cancellation handling.
- `java/` contains the Java helpers for database setup and real window capture.
- `test_tutorial_maker.py` checks the main features.

Keep these files together when copying or uploading the project. Run `python -m unittest test_tutorial_maker.CoreTests` for the checks that do not open Java windows.

## Requirements

- Windows with an unlocked, visible desktop during screenshots.
- Java JDK 17 or newer. Your computer's Java 25 installation was detected.
- Python 3.10 or newer with Tkinter. The launcher uses the available bundled Python runtime on this computer; if it is removed, install Python and run `py -m pip install -r requirements.txt`.
- An OpenAI API key with API billing enabled. The default model is `gpt-4.1`; change it in Settings if needed. Tutorial text is sent to OpenAI. Your name and registration number are added locally to the final document, rather than included in the AI prompt.
- For JDBC questions, a running MySQL server and an account that can create a new database and its tables. The default connection is `127.0.0.1:3306`. The app downloads the official MySQL Connector/J driver from Maven Central on first use and checks its SHA-256 checksum. The existing server was not reachable at that address during setup; check the host/port used by your MySQL client.

Keys and database passwords are kept in memory and never intentionally written to settings, answers or logs. The Java subprocess receives the database credentials it needs, but not the OpenAI API key.

## Linux

Install Python 3 with Tkinter, a JDK 17+, and Xephyr (Arch: `python tk jdk-openjdk xorg-server-xephyr`; Debian/Ubuntu: `python3-venv python3-tk default-jdk xserver-xephyr`). Then:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
./run.sh
```

`run.sh` starts a nested Xephyr X server on the first free display (from `:2`, 1366x768), runs the app inside it with the venv's Python, and stops Xephyr when the app exits. This is needed because `java.awt.Robot` screenshots are unreliable under XWayland (on Hyprland every capture failed the "obscured" check); Xephyr gives Java a real X11 screen. Generated program windows appear inside the Xephyr window. Override the size or starting display with `XEPHYR_SIZE` / `XEPHYR_DISPLAY`.

MariaDB works in place of MySQL for the JDBC questions: the bundled MySQL Connector/J handles basic JDBC against it. Start the server, create a user that can create `tutorial_...` databases, and enter that login in Settings.

## Output

Each run creates its own directory inside `output`. The Word document contains the tutorial title, name, registration number, subject, each original question, labelled Java files, database setup where applicable, and actual output screenshots. Code has no comments and uses four-space indentation and same-line braces. The program requests this formatting from the AI; it does not claim to disguise authorship or use the C language.

Swing screenshots come from running the generated application and using its real controls. Console screenshots show a real window containing stdout/stderr captured from the Java program. They are not screenshots of IntelliJ or an online compiler. Keep other windows out of the way while captures run. Long console output may require adjusting the demo or viewing `stdout.txt` for the complete transcript.

Each question gets up to three generation/repair attempts. The app compiles each answer, runs a demo, checks asserted output and captures screenshots. These checks are generated by the same AI and are not a guarantee of complete correctness; review the code, question coverage and images. A failed question is marked as pending in an **INCOMPLETE** document instead of receiving a fabricated screenshot. `Progress.docx` preserves finished questions after each step. Stop cancels a Java process promptly; an active network request can take up to 180 seconds to return.

The generated source files, SQL, inputs, screenshots, assertions, execution logs and repair errors are saved alongside the document. Each database attempt creates a separate `tutorial_...` database, records its name in `database.txt`, and leaves it in MySQL for inspection. No existing database is selected for setup. You can remove the recorded demonstration databases later in your MySQL client.

## Scope

This is a local Java tutorial helper, including Swing/MVC and JDBC/MySQL assignments like Tutorial 9. It reads text and tables in their original order. It does not OCR scanned pages or interpret embedded diagrams. For documents without clear sequential question numbering, AI identifies question boundaries. Check `questions.json` if the source uses unusual formatting.

Generated Java runs with your local user permissions; this is not an execution sandbox. Use trusted coursework. The app limits filenames, strips code comments, excludes some process/automation constructs, avoids passing unrelated environment secrets, and uses timeouts. Those checks do not make arbitrary code safe.
